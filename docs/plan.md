# FileProcessor — план реализации

Windows-утилита для массового переименования файлов в папке по шаблону
на псевдоязыке. До 10 000 файлов в папке, многопоточная обработка,
прогресс и ETA в окне и в системном трее.

## 1. Технологический стек

- **Язык/фреймворк**: C++20 + Qt 6 (Widgets). Ядро (`fp_core`) — чистый C++
  без Qt, чтобы собирать и тестировать его на любой платформе.
- **Сборка**: CMake + Ninja; целевой компилятор — MSVC (разработка ведётся
  кроссплатформенно).
- **EXIF**: header-only библиотека (TinyEXIF/easyexif) — Qt 6 не читает дату
  снимка из EXIF.
- **Тесты**: собственный минимальный фреймворк (`tests/minitest.h`),
  ноль внешних зависимостей.
- **Хостинг/CI**: sourcecraft.dev, конфигурация в `.sourcecraft/ci.yaml`.

## 2. Архитектура

```
┌─────────────────────────────────────────────┐
│ UI: MainWindow, две панели, tray, прогресс  │  src/ui      (Qt Widgets)
└──────────────┬──────────────────────────────┘
┌──────────────▼──────────────────────────────┐
│ Core:                                       │  src/core    (чистый C++)
│  • Template       (псевдоязык → AST → eval) │
│  • RenamePlanner  (AST + файлы → план)      │
│  • RenameExecutor (многопоточное выполнение)│
└──────────────┬──────────────────────────────┘
┌──────────────▼──────────────────────────────┐
│ Infra: FS-операции, EXIF-ридер, журнал undo │  src/infra
└─────────────────────────────────────────────┘
```

Ключевая идея — **двухфазное переименование**:

1. **Планирование** — для каждого файла вычисляется новое имя, проверяются
   коллизии (дубликаты, занятые имена, циклы A→B, B→A) и валидность имени
   под Windows. Результат планирования — содержимое правой панели
   предпросмотра.
2. **Исполнение** — план применяется многопоточно, с журналом выполненных
   операций (`old → new`) для отката при ошибке или отмене.

## 3. Псевдоязык шаблонов

Полная спецификация: [template-language.md](template-language.md).
Кратко: статический текст + токены в `{...}`; связки `=` (формат),
`AND` (дополнительный модификатор), `OR` (запасной вариант); ключевые
слова — только англоязычные, регистронезависимые.

```
{folder}_{number = 0001}.{ext}                          → Vacation_0001.jpg
Photo_{photodate = YYYYMMDD OR filedate = YYYYMMDD}_{number = 001}.{ext}
{name AND uppercase}_{number = 01}.{ext}                → SCAN_01.pdf
```

## 4. Многопоточность и неблокирующий UI

- **Сканирование папки** — в отдельном потоке, результаты отдаются в модель
  пачками по ~500 файлов.
- **Предпросмотр** — пересчёт при правке шаблона с debounce ~300 мс,
  параллельное вычисление имён; EXIF кэшируется по файлу.
- **Исполнение** — пул потоков (4–8 воркеров, операция I/O-bound), файлы
  нарезаются на батчи; атомарный счётчик прогресса, сигнал в UI не чаще
  ~10 раз/сек.
- **Отмена** — кооперативная (`std::atomic<bool>`), с предложением отката
  по журналу.
- **ETA** — скользящее среднее (EMA) скорости «файлов/сек», отображается
  в статус-баре и в tooltip tray-иконки.

## 5. UI

- **MainWindow**: выбор папки (+ история), поле шаблона с подсветкой ошибок
  и шпаргалкой по токенам; две синхронно скроллируемые панели `QListView`
  (слева текущие имена, справа будущие; конфликты — красным); прогресс-бар,
  счётчик, ETA, кнопки «Применить»/«Отмена».
- **Tray**: `QSystemTrayIcon` — состояние, tooltip с процентом и ETA,
  уведомление по завершении, меню (показать окно / отменить / выход).
- **Windows-специфика**: прогресс на кнопке таскбара через `ITaskbarList3`.

## 6. Надёжность

- Валидация имён Windows: запрещённые символы `\/:*?"<>|`, зарезервированные
  имена (`CON`, `NUL`, …), длинные пути (`\\?\`-префикс).
- Разрешение коллизий: пропустить / суффикс `(1)` / остановиться — на выбор.
- Журнал операций на диске → Undo последней операции даже после перезапуска.
- Кнопка «Применить» активна только при плане без конфликтов.
